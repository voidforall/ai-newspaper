# 10 — 给重点事件提供时间线、新增变化与更正

**状态：** 待评审草案，尚未发布到 GitHub Issues。

## 交付行为

读者打开一个重点事件，能看到前次报道、这次新增的事实及更正，已经发布的历史期刊不被静默改写。

## 阻塞依赖

05、06。

## 验收条件

- [ ] 至少选择三个真实重点事件，维护者可将多个来源/日期归到稳定 eventId，不依赖标题字符串自动生成身份。
- [ ] 事件页按时间展示已发布报道及可定位证据，区分首次发布、开放使用、独立验证和更正等新增事实。
- [ ] 每日新闻可链接前次报道并说明新增；缺乏新增证据时不凭空生成变化。
- [ ] 更正包含原因、时间与原说法；更新事件当前状态不会修改既有期刊快照，必要修订有可见记录。
- [ ] 演示同一事件跨至少两次更新与一次更正；检查误合并可以拆分并保持历史链接可追踪。

## 范围边界

不要求作为 v0.1 阻断项；先手工维护，不建向量数据库或全自动事件图谱。
