# 11 — 用试读反馈验证定位，并准备公开发布素材

**状态：** 待评审草案，尚未发布到 GitHub Issues。

## 交付行为

通过一轮小规模试读判断报纸是否值得回来，再用真实成品准备面向读者与开源维护者的发布材料。

## 阻塞依赖

09。

## 验收条件

- [ ] 准备面向 10–20 名 AI 开发者的试读说明和反馈表；实际邀请或发消息须由用户明确授权。
- [ ] 在至少一周试读后汇总受访人数、回访意愿、证据使用体验、具体有用/无用案例；未取得数据时不编造完成。
- [ ] 将至少五位明确愿意持续订阅并举出具体价值作为探索目标，未达到时解释是定位、内容还是分发问题并提出下一轮实验。
- [ ] 准备三份真实样例、可录制的 30–45 秒演示脚本、中文/英文发布文案；只宣传实际上线能力，事件时间线未上线时不作承诺。
- [ ] 分别给出读者订阅路径和维护者 fork/贡献路径，列出拟投递社区及发布前需要核实的规则；未经授权不发帖、联系或公开发布。
- [ ] 记录发布后的回访、订阅意愿和分享带回阅读的直接观察方法；不为测量引入账号、追踪后端或编造渠道归因。

## 范围边界

10 可以独立推进，但不是试读或首次公开发布的硬依赖；推广素材不能冒充真实用户验证。
